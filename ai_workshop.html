🗣️ ② 第一階段：Prompt 實戰（產生專題企劃）

為了讓後面的實作有連貫性，我們不要每次都叫 AI 寫新東西。現在，我們第一步先來規劃「教學遊戲的文本與題庫」。

推薦使用 ChatGPT 或 Google Gemini 進行這一步驟。

💡 核心觀念：把 AI 當成「坐在對面的專家」

很多人學 Prompt 的迷思是：「我必須一次寫出完美的指令」。其實真正高效的做法是「對話與討論」，而不是單向要求：

  1. 先拋出想法：「我下週要教六年級『電與生活』，想做一個互動遊戲，你有什麼點子？」
  2. 收斂與聚焦：「我覺得你提的『導體與絕緣體分類』不錯，請列出 10 個生活常見物品的題庫給我看看。」
  3. 請 AI 自己寫 Prompt：「我們剛剛討論得很棒。現在請你把剛才確認的企劃與需求，總結成一段精準的『Prompt 指令』，讓我以後可以直接貼給你，快速產出其他單元的類似企劃。」
小提示：與其自己絞盡腦汁背誦指令框架，不如學會把 AI 當成同事，討論完再叫它自己把結論寫成指令！

✍️ 動手實作：您的第一輪討論起手式

不要急著下滿滿的限制條件，請直接複製以下這個「填空題」送給 AI，開啟你們的對話：

我下週要教【 _______ 年級】的【 _______ 科目】。 單元主題是：「【 ______________ 】」。 我想要讓學生玩一個簡單的網頁分類小遊戲來複習。請你扮演一位資深教師，先幫我發想這個遊戲的「文本與題庫」。 請給我 10 個適合這個單元的分類項目（請幫我分成兩大類，各 5 個），並附上學生答錯時的「提示短語」。 ⚠️ 注意：先不要寫任何程式碼，只要用表格給我企劃內容即可。

接續討論：當 AI 給出表格後，您可以繼續回覆：「我覺得第三個題目太難了，換一個生活化一點的」，直到企劃完美為止！

💎 進階概念：從一般 Prompt 升級為 Gems 與 Skills

當我們把剛才那種「長篇大論的 Prompt」用得越來越熟練後，您可能會覺得每次都要複製貼上很麻煩。這時，我們就需要認識 Gems (專屬指令) 與 Skills (技能) 的概念：

什麼是 Gems (指令包)?

簡單來說，Gems 就是把「角色、情境、限制」等長篇的背景設定「打包存檔」。
例如：您可以建立一個名為「自然科教案大師」的 Gem，把剛才那一大段前提都寫進去。未來只要直接對這個 Gem 說「今天我想教：牛頓第一運動定律」，它就會自動用之前設定好的規格來產生教案。
（目前 ChatGPT 的 Custom GPTs 或 Gemini 的 Gems 就是這種功能）

什麼是 Skills (工具技能)?

Skills 比 Gems 更進一步。它不只是「講話的範本」，而是賦予 AI 「動手做事」的能力。
例如：您可以給 AI 一個「讀取電腦資料夾」或「開啟瀏覽器查資料」的 Skill。
⚠️ 限制：Skill 通常需要搭配具有執行權限的 Agent（代理程式）才能使用，例如工程師用的 Cursor 或 Claude Code。在一般網頁版中，像 Gemini 的進階 Skills，目前通常只開放給特定付費的 Advanced 帳號使用。

給老師的建議：今天我們依然會使用一般 Prompt 來實作，因為這是最基礎、在任何免費平台都能用的技巧。但理解 Gems 與 Skills，能讓您預見未來備課「全自動化」的可能性！

🎨 ③ 第二階段：Canvas（把企劃變成互動雛型）

有了上一步的表格題庫後，我們不要自己辛苦重打。直接延續剛剛的對話視窗，使用支援程式碼渲染的平台（如 Claude Artifacts 或 Gemini）讓它一鍵變成網頁。

🔗 接續上一步的指令

太好了，這個題庫很棒！ 現在請根據你剛才提供的「10 個物品清單」，幫我寫一個單一檔案 (HTML+CSS+JS) 的網頁互動遊戲。 介面與功能需求： 1. 畫面上方有兩個大區域：「導體區」與「絕緣體區」。 2. 畫面下方會隨機出現那 10 個物品的卡片。 3. 學生可以點擊卡片，再點擊對應的區域來分類（或者提供拖曳功能）。 4. 放對時卡片變綠色並消失，放錯時顯示你剛剛設計的「提示短語」。 ⚠️ 請輸出完整的 HTML 程式碼供我預覽。

👁️ Canvas 實作預期結果

  • 此時，您的右側畫面應該會直接跳出一個「可以玩」的小遊戲雛型。
  • 老師親自玩玩看：您會發現它堪用，但可能很陽春、顏色很醜，或者是「用手機螢幕看的時候，兩塊區域擠在一起變形了」。
  • 👉 不要立刻在 AI 網頁裡叫它修！ 這會落入下一節要講的「Token 陷阱」。

🛠️ ④ 第三階段：Vibe Coding（用外部編輯器局部除錯）

一開始用網頁版生出雛型很快，但當您在 Canvas 裡一直說「幫我改按鈕顏色」、「幫我修手機版」時，常常會遇到：AI 把整個記分板功能搞壞、或是突然吐出殘缺的程式碼（鬼打牆）！

因為網頁版 AI 每次修改，經常是「整份檔案幾百行重寫」，極易出錯且浪費額度。

🔧 解法：引入外部編輯器進行「部分修改」

將剛才 Canvas 產出的 HTML 程式碼完整複製，貼到電腦裡的外部編輯器，只讓 AI 針對壞掉的地方進行「局部手術」。

推薦編輯器工具

  • VS Code：微軟免費的文字編輯器。把程式碼貼上去，只複製壞掉的那一段函數給 AI，讓它修好後再貼回 VS Code 取代。
  • Cursor 或 Claude Code：內建 AI 的進階編輯器。直接輸入「幫我把 index.html 裡的手機版排版修好」，它會自動找到該段落並修改。

這樣做的巨大優勢

  • 不會牽一髮動全身：原本好的功能絕對不會被 AI 誤刪。
  • 省下大量 Token：不用每次都讓 AI 讀取／吐出幾千行無關的程式碼。
  • 找錯更精準：有了行號，您更容易告訴 AI「第 45 行到 60 行的畫面在手機上怪怪的」。

💬 外部協作的除錯指令示範

請不要重寫整個專案，我只提供 CSS 中 `.container` 與 `.drop-zone` 相關的程式碼給你。 問題：用手機版觀看時，導體與絕緣體兩個大區域太寬，超出了螢幕。 要求： 1. 保持桌機版的左右並排排版不變。 2. 螢幕寬度小於 600px 時，將這兩個區域改為「上下排列」，寬度 100%。 3. 請先說明你要修改哪幾個屬性，再給我「修改後的那一段程式碼」即可。 （在此貼上您從編輯器複製出來的一小段 CSS 程式碼）

🚀 ⑤ 第四階段：專題擴充（完成您的專屬大作）

現在，您的「導體與絕緣體」遊戲不僅能動，而且在手機上也很完美了！最後一步，我們要利用外部編輯器，把這個雛型擴充成「完整的大作」，並替換成您自己的學科。

📚 任務 1：替換為您的學科內容

在您的 VS Code 裡找到剛剛的「題庫清單 (Array)」。您可以直接手動修改，把「鐵釘、塑膠尺」換成「國語成語」或「歷史事件」，遊戲邏輯完全不用動！

🕹️ 任務 2：增加進階遊戲機制

複製您完整的程式碼給 AI，加上這段指令：
「請在現有基礎上，幫我加上 60 秒倒數計時器，以及當 10 個物品都分類完成後，會跳出『過關！您的總得分是 X 分』的彈出視窗動畫。」

🌍 ⑥ 發布作品：讓成果變成真正的網站

做好的網頁，大家一定會想：「Gemini 或 Claude 右上角不是有 Share (分享) 按鈕嗎？直接給學生這個網址不就好了？」

🤔 為什麼我們不推薦直接用 Canvas / Artifacts 分享？

依賴 AI 平台內建分享，在教學現場會遇到極大的災難：

  • 網址冗長且會變動：每次您發現錯字修改後，通常必須「重新產生一個新網址」，導致舊網址失效，學生拿到錯亂的版本。
  • 畫面干擾：分享出去的畫面常帶有 AI 平台的 Logo 或對話介面，看起來不像一個純粹獨立的「教學網站」。
  • 生命週期受限：有些平台的分享快取只要過了一段時間，或是平台政策改變，網址就會無預警失效。

🏆 真正的解法 (專業發布路線)

我們將使用工程師標準的免費流程，讓您的作品永久、穩定地活在網路上：

1. 本機端
確認您的 index.html 在電腦上運作正常。
2. GitHub
將程式碼免費存放到 GitHub（您的雲端原始碼保險箱）。
3. Vercel
到 Vercel 綁定您的 GitHub。它會自動幫您變成一個 24 小時運作的真實網站！
最大好處：未來只要在 GitHub 修改任何一個錯字，學生的網址不用換，重整畫面就會自動更新為最新版！

🦸 不會發布怎麼辦？讓 AI 當你的專屬助教！

沒碰過 GitHub 或 Vercel 聽起來很嚇人？別擔心，你完全不需要背任何複雜的「終端機指令碼」。你已經有地表最強的工程師坐在你對面了，直接開口問 AI！

💡 試著把這段指令直接貼給 ChatGPT 或 Claude：

🤖 ⑦ 突破限制：AI Agent 概況與「Token 額度」窘境

經過剛剛的開發流程，若您的專案稍微複雜一點，您可能已經遇到 AI 提示：「您的免費使用量已達上限，請 4 小時後再試。」

📈 目前 AI Agent 的發展概況

Agent（代理人）不只是回答問題，它會「使用工具」幫你完成任務。主流有幾種形式：

  • 網頁端 Agent：如 ChatGPT Plus 內建搜尋、繪圖與資料分析。
  • 程式開發 Agent：如 Cursor 或 Devin，它們會自動讀取你電腦的檔案，幫你改 Code 甚至自己除錯。
  • 瀏覽器 Agent：幫你自動點擊網頁、抓取資料並填寫表單。

💸 現實的打擊：未付費額度為何秒殺？

Agent 雖然強大，但有一個致命傷：超級吃 Token（運算資源）。

  • 為了理解整個專案，Agent 每次動作都需要讀取大量的上下文歷史對話。
  • 我們以為只是問了「一個問題」，但它在背後可能會自己思考、測試、失敗再重來好幾次。
  • 結果：免費版的額度可能不到 10 分鐘就見底，直接中斷您的備課節奏。

🔥 實境解析：Agent 是如何「燒掉」你的 Token 的？（以 antigravity 代理為例）

假設您使用一個名為 antigravity 的網頁瀏覽代理程式，只輸入了一句看似簡單的指令：「幫我查 3 個最新的自然科互動小遊戲並寫成摘要」。

您以為這只算「對話 1 次」，但 Agent 在背後其實像滾雪球一樣，默默狂燒您的額度：

第 1 圈
【擬定計畫】讀取您的指令，思考：「我應該先去 Google 搜尋關鍵字」。（消耗約 500 Token）
第 2 圈
【執行搜尋】呼叫搜尋引擎。為了不忘記任務，它必須把「您的指令 + 剛才的計畫 + 搜尋回傳的 10 筆結果」全部打包讀一次。（消耗約 2,500 Token）
第 3 圈
【遇到錯誤】Agent 點進第一個網頁，發現被防禦機制擋住進不去。它想：「糟糕，我得換一個網頁」。此時它必須再次讀取「指令 + 計畫 + 搜尋結果 + 剛才的錯誤紀錄」。（消耗約 4,500 Token）
第 4 圈
【閱讀網頁】終於成功進入第二個網頁。它把網頁裡長長的文章、側邊欄、廣告文字全部吞下去，試圖找出遊戲摘要。（消耗約 9,000 Token）
第 5 圈
【統整輸出】為了把報告寫出來，它必須帶上「前面 4 圈的所有記憶」，才能打出最後那 300 字的摘要給您。（消耗約 15,000 Token）
殘酷真相：您覺得只問了 1 個問題，但 Agent 為了「自主幫您解決困難」，實際上在背後與伺服器來回溝通了 5 次，並且每次記憶體都會加倍疊加！這就是為什麼您的免費次數總是會在一瞬間被扣光的原因。
